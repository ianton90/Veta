# Decisions

Short log of project decisions. Newest last.

| # | Date | Decision | Why |
|---|------|----------|-----|
| 1 | 2026-10-09 | Rust, Cargo workspace (`veta-core`, `veta-gui`, `veta-cli`, `veta`) | Separate UI-free core shared by GUI and CLI. |
| 2 | 2026-10-09 | GUI with `iced` (latest stable) | Owner's choice; pure Rust, cross-platform. |
| 3 | 2026-10-09 | `arrow` + `parquet` instead of `polars` | Full control over writer settings, encodings and metadata; far fewer dependencies and faster builds. Cost: larger-than-memory operations (e.g. sort) are ours to write. |
| 4 | 2026-10-09 | `clap` for the CLI | De facto standard; generates help and validates arguments. |
| 5 | 2026-10-09 | `rfd` for file dialogs | iced has no native file dialogs. |
| 6 | 2026-10-09 | `serde` + `toml` for themes, config and recipes | `serde` maps TOML text onto Rust structs automatically instead of hand-written parsing. |
| 7 | 2026-10-09 | MVC: all data changes go through `Command`s in `veta-core` | One code path for GUI, CLI and undo/redo. |
| 8 | 2026-10-09 | Data changes are Power Query-style applied steps | Inspectable, reorderable, replayable from the CLI. |
| 9 | 2026-10-09 | Files above a memory budget are paged by row group | Must handle files larger than RAM. |
| 10 | 2026-10-09 | Save preserves the source file's writer settings | Owner requirement; defaults only for new files. |
| 11 | 2026-10-09 | Apache-2.0 license | Free to fork and use; attribution required. |
| 12 | 2026-10-09 | Branches: `dv` development, `pr` release. No CI. | Owner's setup; checks run locally before pushing. |
| 13 | 2026-10-09 | Enable arrow's `chrono-tz` feature | Needed to display timestamps with named time zones (e.g. `UTC`, `Europe/Madrid`). |
| 14 | 2026-10-09 | Files are read in chunks of 64k rows within row groups, cached LRU under the memory budget (default 1 GiB) | Memory stays bounded even when a single row group is larger than the budget. |
| 15 | 2026-10-09 | Grid is a custom iced widget drawing only visible cells | iced has no table widget; a custom widget keeps scrolling smooth on millions of rows. |
| 16 | 2026-10-09 | Icons: a subset of the Lucide icon font vendored in `crates/veta-gui/assets` (ISC license) | No extra crate (an SVG renderer would pull in many); 18 KB. |
| 17 | 2026-10-09 | Themes are TOML files; two built in, users add more in `<config dir>/themes` | Owner requirement; easy to share and edit. |
| 18 | 2026-10-09 | Settings in `<config dir>/config.toml`; config dir resolved by hand (`%APPDATA%`, `~/Library/Application Support`, `$XDG_CONFIG_HOME`), overridable with `VETA_CONFIG_DIR` | Avoids a dependency for three paths. |
| 19 | 2026-10-09 | Font family and size apply on restart; colors and light/dark switch live | iced sets the default font at startup. |
| 20 | 2026-10-10 | Cell edits and row insert/delete refer to rows by position at their step. Changing an earlier step warns the user instead of tracking row identity. | Owner's choice: simpler, and stable IDs cause surprises after sorting. |
| 21 | 2026-10-10 | Consecutive cell edits stay grouped in one step; each edit undoes on its own. | Keeps the steps list readable. |
| 22 | 2026-10-10 | Steps that need a full pass (filter, sort, fill) cache their result: filters keep the surviving row ranges; sort/fill materialize their output in memory for in-memory files, or to a temporary Parquet file for paged files. Computed in the background; changing a step drops the caches from that step on. | Full results scrollable for files larger than RAM. |
| 23 | 2026-10-10 | Changing an earlier step may break later ones; they are marked with the error, not refused. Saving and adding steps are blocked until fixed. | Same as Power Query. |
| 24 | 2026-10-10 | Date/time formats in Cast use our own parser for a strftime subset (`%Y %y %m %d %b %B %H %I %p %M %S %f`) | `chrono` would need a direct dependency (arrow does not re-export it); about 150 lines instead. |
| 25 | 2026-10-10 | Computed columns use a small expression language parsed in core: `[Column]` or bare names, `+ - * / % &`, comparisons, `and/or/not`, a fixed set of functions. Duplicate and Index columns are computed columns (`[col]`, `row()`). | No dependency; type-checked against the schema so the column type is known without reading data. |
| 26 | 2026-10-10 | `veta-core` uses `serde` + `toml` for recipes, through its own recipe types (steps stay serde-free); types written as in `veta schema`, edited cell values as text | Recipes are shared by the GUI and CLI; keeps arrow types out of the file format. |
| 27 | 2026-10-11 | Row filtering is a temporary view (not a step), computed in the background; the table is read-only while it is on. Keep/Remove Rows turn it into a filter step (Remove = inverted). Right-click Keep/Delete rows act on the selection. | Owner: separate filtering from keeping, like Excel. |
| 28 | 2026-10-11 | Recipes are JSON via `serde_json` (replaces the TOML of 26): metadata plus `steps`, each with `order`, `type`, `description`, `settings`. `veta-core` no longer uses `toml`. | Owner: readable by people, not just parsers; `serde_json` approved. |
| 29 | 2026-10-11 | CSV/JSON import and export use arrow's `csv`/`json` readers and writers (part of the approved `arrow` crate). Imports read all CSV columns as text and convert them with the cast logic (invalid values become null; decimal comma supported); results go through a temporary Parquet file, loaded into memory if they fit the budget, paged otherwise. Encodings: UTF-8, Latin-1, Windows-1252 and UTF-16 (decoded by hand; a UTF-16 byte order mark is detected). | No new crates; large files stream. Other encodings (Cyrillic, CJK, …) would need `encoding_rs`. |
| 30 | 2026-10-12 | CSV import never drops invalid values silently: by default they are kept as text in a `<column> errors` column (only for columns with failures); "set to null" and "stop" are options. The count per column is always reported. | Owner: failing silently is not acceptable. |
| 31 | 2026-10-12 | Two binaries: `veta` (desktop app, files as arguments, Windows GUI subsystem) and `veta-cli` (headless commands). Replaces the single `veta` binary with subcommands. | Owner: simpler on every OS; no console window behind the app on Windows (#59); CLI runs in parallel freely; the app's arguments are free for files and single-instance handling (#60). |
| 32 | 2026-10-12 | Single instance over Unix domain sockets on all OSes, in a per-user private directory; Windows uses the `uds_windows` crate (new on Windows: `tempfile`, `memoffset`) until `std::os::windows::net` is stable. No loopback TCP. | Owner approved. Access is controlled by file permissions, unreachable by browsers and other users; one code path; our code keeps `unsafe_code = "forbid"` (#60). |
| 33 | 2026-10-13 | Versions are SemVer `MAJOR.MINOR.PATCH` (first release 0.1.0); each build also has a build number (`$VETA_BUILD_NUMBER` or the commit count) and commit hash, shown in About/`--version` and later in the Windows file version's 4th field and the macOS build number. Release archives come from `scripts/release.sh`. | Owner: Cargo, MSI upgrades and macOS bundles all expect three-part versions; a four-part version only fits Windows file metadata. See `docs/RELEASING.md`. |
| 34 | 2026-10-13 | Packaging (#51): Windows installer with NSIS (per-user, no admin; built on Linux with `makensis`), exe icon and version info via the build-time crate `embed-resource` (`veta` only), Linux AppImage (`appimagetool`, fetched at build time), macOS `.app` + `.dmg` built on a Mac with `hdiutil`. Icon drawn as SVG (`packaging/icons`), rendered files committed. | Owner's choices. NSIS builds without Windows; nothing new ships inside the app. |
| 35 | 2026-10-13 | `serde_json` with its `preserve_order` feature (uses `indexmap`, already in the build through arrow). | Editing a nested value keeps map keys and JSON object keys in their order instead of sorting them (#81). |
| 36 | 2026-10-13 | Ribbon redesign (#88): tabs Home (incl. file commands), Rows, Columns, Nested, View; no File page, contextual tabs, command search or Quick Access bar; commands that don't apply are greyed out. Clipboard as tab-separated text. Icons regenerated from Lucide 1.56.0 (`scripts/icons.sh`). | Owner's choices. TSV is what spreadsheets put on the clipboard. |
| 37 | 2026-10-15 | Release packages are built by GitHub Actions on version tags (`.github/workflows/release.yml`, from `packaging/ci/release.yml`): Linux in a Debian 11 container (glibc 2.31), Windows with MSVC and NSIS, macOS arm64 and x86_64; the result is a draft release. Checks still run locally; there is no CI on pushes. Replaces "No CI" in 12 for releases. | Owner approved (#86): every OS from one tag, and an AppImage that runs on older distributions. |
| 38 | 2026-10-15 | Code layout (#106): files grouped in folders by purpose, at most two levels below `src/`; a folder's `mod.rs` re-exports what callers use, so old paths (`veta_core::io`, `command`, …) keep working. Unit tests inline when short, in a sibling `tests.rs`/`tests/` when over ~150 lines; integration tests in each crate's `tests/`. The GUI app is split by area, each file ordered message handlers → ribbon actions → helpers. Dialogs that add or edit a step implement `StepDialog` and share one `Dialog::Step` / `Message::Step` path. Struct field and list item edits are core commands (`SetField`, `SetListItem`, `InsertListItem`, `RemoveListItem`). | Owner: files had grown to 3–7k lines with tests inside; the layout makes them easier to read and leaves room for more transforms, statistics and formulas. |
| 39 | 2026-10-15 | No Value tab and no Edit as JSON dialog (#117): nested values are edited in the grid. Map entries edit in the grid (#118, #120); values at any depth too, see 41. | Owner: the grid is the app's editing surface; a side tree and a JSON dialog are workarounds. |
| 40 | 2026-10-15 | Version 0.2.0. 0.1.0 was never tagged or released; the first release will be 0.2.0. | Owner: the app has grown well past what 0.1.0 described. |
| 41 | 2026-10-16 | Nested values at any depth (#99). Core: a `Node` is one value inside an Arrow array (no copy) whose children (struct fields, list items, map entries) are nodes too; a path of `Field`/`Index`/`Entry` steps addresses any value, and `SetValue`, `InsertItem`, `RemoveItem`, `SetKey` replace the per-type commands (each still rewrites one cell through its JSON). Grid: opening a row lists the first level of its nested cells; each struct, list or map line then opens on its own (its arrow or Space), indented. Structs, lists and maps are not typed as JSON in the GUI: Enter goes into them, typing adds an item to a list or map, and the formula bar is read-only on them. Add column / Add field build nested types with one indented picker per level. | Owner: one model for all three types and any depth; JSON is for files, not for editing. |
| 42 | 2026-10-18 | Version 0.3.0. 0.2.0 was never tagged or released; the first release will be 0.3.0. | Owner. |
| 43 | 2026-10-18 | Memory budget defaults to half of RAM (#130), replacing the fixed caps; work that doesn't fit uses temporary files. Row-group parallelism (#128) and a sample sort (#129) follow the #105 analysis. | Owner. |
| 44 | 2026-10-18 | `sysinfo` (feature `system` only) reads the machine's RAM for the default memory budget (#130). | Owner: Windows has no safe way in std, and the workspace forbids unsafe code. |
| 45 | 2026-10-19 | Paged sorts use a sample sort by key range (#129) instead of sorted runs and a k-way merge: no single-threaded merge, buckets sorted on all cores, small enough to stay cache-friendly. Rows equal to a cut value get their own bucket (already in order), so heavily repeated keys don't make one huge bucket. | 2 GB, 4 cores: 28–30 s → 23–24 s; the merge didn't scale with cores. |
| 46 | 2026-10-19 | `mimalloc` (Microsoft Research's allocator, a small C library) as the global allocator of `veta` and `veta-cli`, as polars uses on Windows. Don't remove it without measuring large sorts and saves on Windows. | Owner. Rust's default on Windows is the system heap: blocks above ~512 KB–1 MB go straight to the OS and back on every allocation and free, so each new large buffer is fresh pages the OS must map and zero, and all threads share one heap lock. Veta's full passes allocate and free multi-GB buffers, so on Windows most of the time went there: sorting 10 GB took 145 s with the system allocator, 41 s with mimalloc (polars 47 s). mimalloc keeps per-thread pools and reuses freed memory. Linux's allocator doesn't show the problem, so it can't be seen in the Linux dev container. |

| 51 | 2026-10-21 | Translation (#135, #136): one shared `Translations` object (a singleton) in `veta-core`, a map tag → language → text, reached from anywhere with `tr(tag)` / `tr_with(tag, values)`. | 53 | 2026-10-21 | Translation lives in the front ends (#139), replacing where 51 and 52 put it: `veta_gui::i18n` (with `veta-gui/translations/`), not `veta-core`. `veta-core` is the model behind the scenes: plain English messages, codes and enums; another app using it brings its own translations. | 56 | 2026-10-21 | Core errors are codes (#138): `Error::Invalid { code, args, cause }` replaces `InvalidCommand(String)`. `ErrorCode` lists every rejection with its plain English message (`error/codes.rs`), `{name}` placeholders filled from `args`, `{cause}` from the wrapped error; `Display` stays plain English (the CLI shows it). `Error` is `Clone` (library errors behind `Arc`) and a broken step keeps the error itself. | 58 | 2026-10-22 | Font choice (#148): Settings lists the installed font families (from iced's font database, no new crate), searchable; families without letters (icons, emoji, symbols) are left out.
